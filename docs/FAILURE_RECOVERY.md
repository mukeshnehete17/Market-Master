# Market Master — Failure Modes & Recovery Matrix

## 1. System Resilience & Recovery Behaviors

| Failure Scenario | Immediate System Impact | Automated Recovery Mechanism | Final State |
| :--- | :--- | :--- | :--- |
| **Student Refreshes Browser During Active Question** | React component tree reloads; local in-memory state is wiped. | On mount, `App.tsx` calls `GET /api/game/current`. Backend checks `game_players` and active `rounds` in Supabase and returns the authoritative active question, server deadline, and current capital. | Student seamlessly resumes the countdown within 1 round trip with zero lost progress. |
| **Student Refreshes Browser After Locking Position** | React component tree reloads. | `GET /api/game/current` fetches active round; backend detects existing record in `positions` table and returns `pending_position`. | UI immediately renders the locked position overlay with the exact selected option and capital at risk. |
| **Admin Refreshes Browser During Live Game** | React AdminPanel reloads. | Top-level state reads `mm_admin_selected_game_id` from `sessionStorage`. `control_deck_state` queries Supabase for the game, active round status, and real-time orders. | Admin Control Deck immediately reconnects to the live game at the exact current phase. |
| **Temporary Network Disconnect During Submission** | POST request times out or drops in transit. | Client displays retry prompt. If the request actually reached the server, database composite unique index `(round_id, user_id)` prevents double-entry. Next fetch retrieves the locked position. | Zero duplicate risk deductions; student state resynchronizes smoothly. |
| **Supabase Transient Network Outage** | PostgREST queries fail. | Backend catches connection error and raises `DatabaseUnavailable`. Flask global error handler emits controlled HTTP 503 Service Unavailable. Client catches 503 and displays graceful retry banner. | Application does not crash or throw unhandled 500s; system recovers automatically when connectivity restores. |
| **Server Restarts During Competition** | In-memory server processes terminate. | Supabase PostgreSQL is the single source of truth. All game states, round numbers, submitted positions, and balances are stored in persistent tables. | Newly spawned Flask instance continues handling requests with zero state loss. |
| **Host Closes Market While Student Is Selecting** | Student attempts to submit after market closure. | Backend checks `rounds.status`. If `status != 'market_open'`, returns HTTP 409 Conflict with message `"Market has closed"`. Client switches to locked state. | Bid rejected gracefully; no corrupted submissions allowed. |
| **Duplicate Admin Click on "Settle Round"** | Admin double-clicks settlement action. | Backend checks `rounds.status`. The first call transitions status to `'settled'`. The second call detects `status == 'settled'` and aborts without repeating P/L ledger updates. | Zero duplicate capital credits/debits. Total balance integrity preserved. |
